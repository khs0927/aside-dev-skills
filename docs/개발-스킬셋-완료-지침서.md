# 개발 스킬셋 완료 지침서
작성일: 2026-10-20 / 대상: 뭐든 개발하기 위한 범용 구성

## 1. 개요
코딩, 디자인, 서버, 온톨로지, 에이전틱 워크플로우 5종을 Aside 사용자 스킬로 설치 완료.
위치: skills/user/dev-*/SKILL.md
검증: 프론트매터 5/5 PASS, 트리거 매핑 5/5 PASS

## 2. 스킬 목록과 사용 조건
1) dev-coding-workflow
- 조건: 신규 기능, 버그 수정, 리팩터링, API 설계, 코드 리뷰, 테스트, 배포
- 절차: 목표 명확화 > 단계 분해 > 기존 코드 확인 > 최소 구현 > 테스트/린트/타입체크 > 품질 게이트 > 하드닝 > 배포 요약
- 규칙: 기존 유틸 재사용, 명시적 타입, 모호하면 한 가지만 질문 후 가정 명시, 변경에는 회귀 테스트

2) dev-design-frontend
- 조건: UI, 프런트엔드, 랜딩, 대시보드, 게임, 3D, Figma-to-code, 디자인 시스템
- 절차: 화면 목표/사용자/기기 정의 > 재사용 패턴 선택 > 시맨틱·반응형·접근성 구현 > 로딩/빈/에러/모바일 상태 > 시각 검증 > 최적화
- 규칙: 디자인 시스템 우선, Figma는 노드 컨텍스트 먼저, Three.js는 카메라·조작·성능 예산 먼저

3) dev-server-infra
- 조건: 서버, Linux, AWS/Azure/GCP, 네트워크, Docker, K8s, Terraform, CI/CD, 관측성, 보안 하드닝
- 절차: 타깃 식별 > IaC 우선 > 최소 권한 > 관측성 > plan/dry-run 후 배포·스모크 > 롤백 준비 > runbook 기록
- 규칙: 시크릿은 vault/env, DB/DNS/CDN은 매니지드 우선, K8s는 requests/limits·probe·securityContext 필수

4) dev-ontology-knowledge
- 조건: 온톨로지, 지식그래프, RAG 메모리, 엔티티 모델링, 택소노미, 프로젝트 지식 베이스
- 절차: competency question 수집 > 질문 근거로만 엔티티/관계 정의 > 깊이 최대 3 > 표준 어휘 매핑 > RAG/GraphRAG 스키마 변환 > 원본 증거와 함께 1회 ingest > 품질 체크
- 규칙: 최소 모델, 온톨로지는 코드처럼 버전 관리, 구조 변경은 리뷰, 관계는 증거 링크 필수

5) dev-agentic-workflow
- 조건: GitHub 자동화, 멀티에이전트, MCP 라우팅, 자동화 플레이북, 에이전트 평가
- 절차: 확정적 vs 에이전틱 구분 > Markdown+프론트매터 정의 > 읽기전용·샌드박스 기본 > 쓰기는 safe-outputs로 > gh aw compile 검증 > lock 파일과 함께 커밋 > 평가 게이트 > 인간 리뷰
- 규칙: CI/CD 보완용, 최소 권한, 워크플로 1개당 1개 임무, 권한·도구·생성파일 배포 전 검토

- 배포·권한 변경은 인간 확인 후 진행
